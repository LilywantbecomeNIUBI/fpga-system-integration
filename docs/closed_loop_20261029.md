## 专用上位机

`python host/motor_tuner.py` 默认启动离线页面 `http://127.0.0.1:8874/`。上位机只访问已有网关，不打开 COM20，也不绑定视频、推理或 IMU 端口。原 8872 视觉/IMU 状态台保留观测入口与 STOP。

界面包含左右目标/反馈曲线、Q8 PI 参数、电机/编码器方向、占空比、位置、故障与累计非法跳变、单轮选择、显式解锁、STOP、100..5000ms 限时测试和 CSV 日志。CSV 包含配置与运行模式。默认目标为零；解锁本身不发非零目标。参数变化需先停机再解锁。

网关固定限时测试的目标与截止时间，心跳不能改变目标或延长测试；到期 STOP 并释放控制。切换窗口、隐藏/关闭页面会释放控制；失联、故障、网关重启后均不自动重新解锁。页面要求网关具有 `timed_test_supported` 能力，旧进程不会开放解锁。

实际连接须先更新并重启唯一网关，再使用：

```powershell
python host/motor_tuner.py --live --token-file runs/commissioning/sram_static_20261029_143616/session_token.json
```

令牌仅在本机读取，不打印、不提交。不要并行打开第二个 COM20 连接。现有正在运行的现场网关和状态台未由本次改造自动替换；8874 提供离线预览。

## 下一次现场操作

当前物理供电未知。本轮没有执行下载或实车运动，磁盘上的新位流不能证明 FPGA 内当前运行版本。

1. 区分 FPGA 的 USB/逻辑电源和 D157B 电机驱动的 12V 电源。先断开驱动 12V，保持逻辑观测；软件 STOP 不等于物理断电。
2. 复核两路电机、四路驱动信号、AB 编码器与共地。左驱动 P7-21/22，右驱动 P7-23/24；左 AB P7-25/26，右 AB P7-27/36。用户确认编码器使用 3.3V；ADC 已拆离。杜邦线可能松动，先确认接触可靠。
3. 分别手转左、右轮，检查反馈独立、方向可解释、静止稳定及非法跳变。此前左轮一次手转净 -223 计数同时增加 118 次非法跳变，右轮尚未可靠验证；不能屏蔽保护或用闭环加力掩盖此问题。
4. 反馈可靠后，再单独安排 SRAM 下载，重新检查零输出遥测与 STOP/CLEAR/ARM 确认；下载不与转动合并，不烧 Flash。
5. 真正转动前重新确认驱动供电、双轮悬空、线缆和人员状态。之后才由操作员显式解锁与选择单轮限时测试。两轮闭环、方向和物理速度标定仍需实车验收。

旧日志中 `clear_ack` 后 `arm_ack_timeout` 的根因尚未在实物上证实。取消外部许可只消除了该软件依赖，不证明串口下行、编码器接触或电机链路已经恢复。
