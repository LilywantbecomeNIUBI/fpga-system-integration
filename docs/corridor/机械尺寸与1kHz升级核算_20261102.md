## 对窄道转弯的影响

若裸底盘约240.2mm宽，通道仅额外宽100～150mm，则示意宽度约340.2～390.2mm。居中时左右各约50～75mm名义空间，仍需扣除上装、墙面不平、外参和跟踪误差。

对三轮装配STEP进行0.2mm线性挠度网格化，提取各实体网格点的地面投影凸包，以驱动轴中点作为转动参考；转角每0.1°采样0～90°，结果如下。网格计算不是严格解析证明，尚未加入网格/角度离散误差、装配公差或实际安全裕量。

- 最大横向投影宽约362.75mm，出现在约59.1°姿态。因此340.2mm宽的无限直走廊内，至少有中间姿态连名义投影也放不下，不能靠提升控制频率完成原地转向。
- 固定驱动轴位置的0～90°转向，所有姿态的横向包络约389.56mm。390.2mm通道即使选择最有利的轴位置，名义总余量也只有约0.64mm；不具备实际安全裕量。
- 轴放在走廊横向中心时，前部扫掠到轴一侧约262.21mm，超过390.2mm通道的半宽195.1mm；不能把“车宽240mm”当作原地转向直径。
- 以上是直走廊内的固定轴/投影核算，不能直接判定L形角部一定不可达。若角部可平移或加宽，要把完整墙体轮廓输入足迹规划，再判断可行轨迹。

底板前部收窄并有圆角，不能简单用320×240mm矩形对角线400mm替代所有精细可达性判断；矩形可以作为保守包络，但会损失部分可行空间。安全规划可在矩形早筛之后使用保守凸包，并显式膨胀实测裕量。

侧方目标停靠也受上述扫掠限制，不能在普通窄道巡航时直接原地旋转90°。本图纸仍无法确定目标停靠凹位和雷达到车头距离。

## 100Hz慢在哪里

`motor_core.sv`默认每10ms更新轮速PI，PWM载波为10kHz，FPGA时钟为50MHz。100Hz不等于电机最高转速，也不意味着FPGA只能每秒算100次。

`wheel_control.sv`的PI是七拍流水线，名义运算时间约`7/50MHz=0.14us`；1ms周期有50,000拍，PI计算不是当前瓶颈。提升调度到1kHz在该算术量级上有充足余量，但新增测速、CDC和全系统STA仍须验证。

当前100Hz与10ms累计计数测速配套。它是既有实现的调度/测速选择，不是FPGA性能上限；也没有现成证据说明它是本车的最优闭环频率。

此外，默认`SLEW=20`表示每个10ms控制周期最多改变20‰PWM。从0到350‰大约要18次更新、180ms；从0到300‰约150ms。`REVERSE_TICKS=10`要求至少约100ms零输出/低速等待，`STALL_TICKS=50`约对应500ms堵转计数时间。实际触发次序、PI需求和PWM唤醒还会改变总响应。

这些限制与PI运算速度不同。提频时默认保持其物理时间/变化率语义，再根据台架响应决定是否单独调整；不能把提频后电机明显更猛直接归因于闭环性能变好。

## 新窄道方案的控制频率

| 层级 | 设计频率/机制 | 目的 |
|---|---|---|
| 编码器边沿捕获/时间戳 | 50MHz逻辑持续工作 | 不等待控制tick记录边沿 |
| 轮速观测与PI调度 | 1kHz目标 | 降低指令/扰动等待，提供分数轮速估计 |
| 正常PWM载波 | 暂保留10kHz | 与控制调度独立，沿用驱动验证基础 |
| 居中/局部路径外环 | 50～100Hz候选 | 根据新鲜墙线、位姿和光流质量生成指令 |
| IMU | 1kHz原始采样 | 高频传播和相机旋转补偿，另计传感器滤波延迟 |
| 雷达/相机 | 约10Hz/30fps现有配置 | 不因为PI提频而产生更多独立观测 |
| 碰撞安全仲裁 | 有效事件直达锁存路径 | 不等待普通PI或外环周期 |

100Hz到1kHz将“刚错过控制tick”的最坏调度等待从约10ms降为1ms，理想均值由5ms降为0.5ms。以0.2m/s示意，单纯9ms等待差对应1.8mm位移；这不是整车停止距离必然减少1.8mm的保证，完整链路还包括观测、PWM、驱动和机械制动。

潜在收益是轮速指令更新更细、左右轮同步更好、负载扰动恢复更及时，为窄道小幅连续修正和末端减速提供条件。实际超调、稳定时间、低速抖动和定位精度需要对照测量，不能从“频率提升10倍”推出“性能提升10倍”。

暂不把速度环定为10kHz：1kHz到10kHz只再减少最多0.9ms调度等待，而现有编码器信息率、机械响应、驱动和图像采样并未同步提高。如果以后有电流采样/电流环，较高频率更适合分配给电流/转矩内环；当前AT8236路径没有已接入的相电流反馈，不写成已经具备电流闭环。

## 不能直接每1ms清零计数测速

低速时固定短窗没有足够边沿。TI与Microchip的编码器资料均将定时计数与边沿周期测量区分使用，后者更适合低速。[TI eQEP原理](https://www.ti.com/lit/an/spraah1/spraah1.pdf)、[Microchip测速方法](https://onlinedocs.microchip.com/oxy/GUID-AC0E172C-9656-4397-A490-08DF807DE2E8-en-US-2/GUID-E756427D-14C6-4449-A859-9DDA5F2D1B6E.html)。

按历史手转约1500“现有位置单位/圈”、轮径65mm举例（仍不是精确CPR标定）：每个位置单位约0.136mm；当前右轮A相双边沿路径每个真实事件记2单位，约0.272mm/事件。50mm/s时约每5.45ms才有一个这样的事件。如果每1ms直接计数并换算，输出会在0和约272mm/s之间跳，而真实平均速度只有50mm/s。

左轮现有连续性恢复模式与右轮A双边沿模式不同，不能把同一个事件步长假定给两轮；原始解码信息率与缩放后的“每圈位置单位数”也不等价。需要分别验证两轮观测器。

拟采用混合测速：

1. 低速用相邻有效边沿的位移/间隔（T法），保存方向、时间戳和置信度。
2. 边沿较密时用滚动计数窗（M法），每1ms更新，不必每1ms清空全部历史。窗口长度按噪声与延迟选择，长窗口不能冒充新的1ms独立测量。
3. 切换有迟滞并保证输出单位一致，提供分数精度。无新边沿时按观测年龄限制速度可信度；停止、换向、非法跳变、计时回绕和超时均有明确行为，不能无限保持最后速度。
4. 现有位置/遥测接口保持原含义；控制内部用定点分数的counts/10ms等规范化单位，或显式版本化的新单位，避免主机把1ms计数误读成10ms计数。

## 提频时必须一起处理的参数

- **积分**：若误差单位保持一致、连续时间增益不变，1ms离散积分步长应为原10ms的1/10。增加小数位/余数累积，不能把小Ki整数除10截成0。Kp不因调度提高自动乘10；若速度单位改变，需要另行换算全部增益。
- **正常PWM斜坡**：原20‰/10ms对应2‰/1ms。保持相同斜率做首轮对照，随后独立评估是否提高。
- **换向等待与堵转计时**：用物理时间表达。原约100ms换向等待在1kHz下应等价100次；原约500ms计时应等价500次，触发阈值也按规范化速度定义。
- **测速静止阈值**：不能直接保留“±1计数/采样窗”而把窗口缩短10倍，否则静止判据的物理速度会改变。
- **输出饱和、抗积分饱和、禁用复位、STOP和ARM**：继续保留现有优先级。安全停车绕过普通斜坡和正常换向等待，使用经过台架确认的制动动作。
- **测试时间与协议**：100Hz和1kHz采用相同物理输入、相同运动学单位、相同斜坡/等待时长对照，不能仅看更新次数。

推荐实施为新窄道控制配置/独立候选，保持现有100Hz默认入口可回退。先完成测速器和1kHz数字验证，再完成全系统时序和台架对照，最后重整定PI。没有将现有`CONTROL_HZ`单独改成1000。

## 证明收益的对照指标

在相同轮向、负载、电压、速度目标、限幅和斜坡下，记录100Hz/1kHz的上升/稳定时间、超调、稳态轮速波动、左右轮误差、负载扰动恢复、低速停走和终末停车距离。直接采集FPGA控制tick、测速值与应用PWM，20Hz上位机状态不足以衡量1kHz瞬态。
