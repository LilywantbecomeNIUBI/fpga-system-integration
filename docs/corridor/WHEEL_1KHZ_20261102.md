# 1kHz轮速控制候选

2026-11-02：在`codex/narrow-corridor-20261102`实现。此功能升级轮速控制与测速；双墙居中、光流硬制动和目标停靠仍按前面的实施方案推进，不在本次轮速修复中冒充已完成。

## 已实现

- `wheel_speed_hybrid.sv`：控制内部使用signed Q8的`counts/10ms`测速。低速用边沿位移/间隔；较高速用8个1ms桶的滚动计数，按实际事件数在10/6事件阈值之间迟滞切换。支持原解码器每事件±1或±2的不同缩放，不改动原始AB解码算法。
- 计数/时间戳按32位差分处理回绕；转向反号时清除旧方向窗口和进行中的除法。无新边沿时用`max(最近间隔, 当前边沿年龄)`保守衰减，50ms无边沿后归零。该超时意味着极稀疏边沿下不能声称仍有有效连续速度反馈。
- 异常位置跃迁（单拍超过±2）或运算未在下个采样tick前完成产生故障，经`motor_core`锁存为反馈故障并撤销ARM；正常零速不会被当作“传感器有效性故障”。重新启动仍须原有显式CLEAR/ARM。
- `wheel_control_1khz.sv`：1ms PI调度，误差保留分数。Kp/Ki仍沿用旧接口的Q8/100Hz参考语义，积分累加器保留10倍比例，不把小Ki整数除10截断。乘法/积分/抗饱和分拍，输出换算采用32拍恢复除法，没有组合通用除法器。
- 正常PWM斜坡由20‰/10ms等价为2‰/1ms；换向等待仍约100ms。换向还要求没有近期编码器活动，避免尚未建立两边沿测速时把移动误认为静止；最后一次边沿后可能额外等待最多约50ms。
- 原10ms编码器速度遥测、超速/堵转检查窗口保持原含义。默认500ms堵转计时、250ms指令看门狗、序号检查、STOP、输出禁用、10kHz PWM与原00滑行路径不改成另一种行为。本次没有新增主动反转或11硬制动控制。

`motor_core.WHEEL_1KHZ=1`选新路径；默认0保留旧100Hz配置。`brushed_motor_top`、`brushed_chassis/system_top`、`task4_chassis/system_task4_top`均透传该参数。对原来的加速数字测试夹具，`WHEEL_1KHZ=0`时原`CONTROL_HZ`语义仍不变。

1kHz下先触发测速，固定等待36拍，再让PI消费完整新结果。PI从接收tick到输出约38拍；50MHz下新增算术和调度在约1.6us内完成，控制tick间隔严格1ms。这里描述FPGA内部数字路径，不包含电机驱动唤醒、PWM相位、传感器和机械响应。

外部命令/遥测继续是整数`counts/10ms`，不会被上位机误读为`counts/1ms`。本次提高内部反馈分辨率和更新频率，**没有提高旧串口目标值的整数分辨率**，也没有把20Hz遥测变成1kHz完整控制波形。

## 独立入口

在系统集成仓库根目录执行，所有命令均不连接串口、不运行烧录器、不发送电机命令：

```powershell
python tools/corridor/test_wheel.py
python tools/corridor/test_integration.py

# 独立电机时序候选：沿用原独立电机引脚，不能代替M2整机位流
python tools/corridor/build_wheel.py --profile motor --mode pnr

# M2整机候选，冻结全部当前源码并显式开启1kHz
python tools/corridor/build_wheel.py --profile task4 --mode prepare
python tools/corridor/build_wheel.py --profile task4 --mode syn
python tools/corridor/build_wheel.py --profile task4 --mode pnr

# 原统一顶层也可独立准备；显式生成100Hz对照
python tools/corridor/build_wheel.py --profile system --mode prepare
python tools/corridor/build_wheel.py --profile task4 --mode prepare --legacy
```

输出位于`build/corridor/<profile>_1khz或100hz/<时间戳>/`；包含完整源码快照、只改顶层默认参数的显式候选、约束、工程、构建脚本和SHA256清单。不会覆盖`build/system`或原`build/task4`候选。检测到其他高云构建时保留已准备快照并退出，不结束别人的进程。

`motor`候选是原独立电机引脚，`task4`才使用M2引脚。**不能把已通过时序的独立电机候选下载到M2接线，并认为引脚兼容。** 整机上板仍要完整PnR、既有时钟/CDC审计、候选身份和实际接线核对；本次没有下载。

## 已执行的检查

- 新增三组RTL：混合测速的±1/±2、低速分数、年龄衰减、停止、位置/时间回绕、M/T迟滞、换向、异常跃迁及复位；PI的等物理时间斜坡/积分、小正负Ki、分数反馈、抗饱和、100ms换向等待、禁用和理想负载收敛；核心的严格1ms/10ms周期、运算截止、单位、CLEAR/ARM、STOP、250ms看门狗、500ms堵转及双轮隔离。
- 合成低速例子：边沿每5.5ms贡献2位置单位，真实均速为约3.6364counts/10ms。稳态混合测速均值约3.6328；直接1ms计数会在0与20counts/10ms间跳。这个匀速理想输入没有模拟真实电机噪声/负载，不能据此宣称实车速度标准差为零。
- 原10组电机RTL、71项Python回归、引脚一致性和原调参界面脚本通过。既有100Hz默认入口保留。
- 独立电机候选完成Gowin综合/PnR，Setup/Hold=0/0，最差Setup约+2.997ns、最小脉宽+7.36ns、无PR1014；Logic8456、FF7566。证据适用于独立电机候选，不代表含视频M2整机已通过时序。
- 完整M2生产层级已运行1kHz候选：检查相机/网络、MPU6050、原始雷达和扫描上传、混合UART、STOP和观察模式故障隔离。最终证据以本目录`evidence/wheel_1khz_20261102/summary.json`记录的源码哈希及状态为准。

其余已经运行的数字测试与最终冻结版本对应关系见证据汇总。整机PnR/时钟脉宽和CDC签核、实际低速噪声、动态整定和100Hz/1kHz上车对比仍待执行；现有感知/光流时序未决项不被本次独立电机STA覆盖。

## 后续实车收益验证

原增益可以保持同一物理语义用于对照，但不是1kHz已整定参数。先在相同限幅、电压、负载、目标和物理斜坡下比较低速抖动、阶跃超调/稳定时间、负载扰动恢复、左右轮速度误差和停止距离。测速含8ms窗口/边沿周期，不能把1kHz运算等价为1kHz独立机械观测。需要更快或更慢的正常斜坡时单独调整并记录，不能将斜坡变猛误认为PI变好。
