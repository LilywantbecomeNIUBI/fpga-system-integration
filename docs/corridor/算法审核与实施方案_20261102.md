## 统一坐标、误差和时效

车体坐标固定为 `x` 前、`y` 左、正角速度逆时针。雷达原始零度和转向必须经实测外参变换；原提案的防撞框把 `Y` 定为前方，与另一处极坐标约定容易冲突。

每点使用 `p_body = R(yaw_mount) · p_lidar + t_mount`，先转换到车体坐标，再计算墙距、足迹和停靠距离。扫描左右两壁不同时到达，使用逐点时间戳与 gyro/轮里程计去畸变；若协议时间粒度不足，按包/扫描速度估计并计入时序误差。没有去畸变时只允许经试验限定的低速和低角速度。

“左右间隙偏差±1.5cm”先按较严格定义解释为 `|g_left - g_right| < 15mm`。对于对称、平行于巷道的车身，对应中心线误差 `|e_y| < 7.5mm`；如果用户指中心线误差±15mm，应单独更改验收定义。转弯时改用全车足迹最小净空和轨迹误差，不能要求两侧固定角度读数始终相等。

STL-27L 近距离标称误差量级为±15mm、标准差5mm；多点拟合能降低部分随机噪声，不能消除安装偏移、材质/入射角偏差。因此严格居中和±10mm停靠都要做实测误差预算，不能只凭滤波窗口推导保证。[产品规格及原厂资料入口](https://www.dfrobot.com/product-2726.html)。

## 居中与转弯算法

1. 过滤无效范围、零强度、CRC/时效异常和车体自反射点。将侧面及前侧点按空间邻接分段，保留足够纵向跨度；固定±10°窄窗口仅作辅助检查。
2. 用有界假设数的直线一致性筛选，再对内点做 TLS/带权拟合。FPGA 使用固定最大点数/迭代数，避免无界 RANSAC；近纵向墙也可在限定斜率下用定点最小二乘。
3. 选取满足左右关系、方向近似平行、宽度一致、连续长度和历史连续性的墙对。拟合失败、残差过大、点数少或数据过期时，减速并进入受限保持/停车，不能跳到“最近物体当墙”。货架开口和杯子属于局部结构，不应直接拉动墙线。
4. 对近似平行墙 `y = m x + b_L`、`y = m x + b_R`，有：

   `e_y = (b_L + b_R) / (2 sqrt(1+m²))`，`e_psi = atan(m)`。

   这里 `e_y > 0` 表示中心线在车左侧，应向左修正；`e_psi` 是参考路径相对车头的角度。轴向直道中 `e_y = (d_left - d_right)/2`。不把原始距离差直接叫中心线位移。

5. 直道候选控制律为 `omega_ref = sat(k_y e_y + k_psi e_psi - k_r(r_meas-r_ref) + v kappa_ref)`，各项单位和符号统一。`e_psi` 项是航向比例反馈，`r_meas` 才是角速度阻尼；不能把任意全局 yaw 数值叫作 D 项。增益随速度验证，转向和加速度有硬限值。
6. 拐角识别前后墙段，生成连续、可行的局部中心路径，以现有 RPP 为起点加入速度/加速度可达窗口。验证整个矩形/多边形车身的扫掠足迹，连同后角、轮胎、摄像头支架和雷达偏心；安全轨迹不存在时停车。

差速运动学为 `v_L=v-B omega/2`、`v_R=v+B omega/2`。这里 `B` 是轮距，不是车身宽度。两轮饱和时联合缩放以保持曲率；指令要满足实测轮速、加速度、死区和换向限制。

不能承诺“通道比车宽多10～15cm就必然能过任意直角”。例如仅作数学示意的220×300mm矩形，中心原地旋转时扫掠直径约372mm；在320mm宽的直走廊无法完成整圈姿态变化。这个计算不等于L形交叉口的精确可达性判定，拐角必须用实际墙体多边形检查。

## 光流突发障碍响应

复用金字塔 LK，但在新窄道控制器中把“观测”和“动作”分开：光流提供障碍证据与有效性，安全仲裁决定停车，不直接采用旧观察器的 LEFT/RIGHT 绕行建议。

推荐增加三类证据：

- **逼近膨胀**：对去旋转后的光流计算局部扩张率/碰撞时间，覆盖正前方逼近。
- **横穿/新进入障碍**：比较与背景运动不一致的连续局部流簇或新遮挡区域；伸手横穿未必产生以画面中心为圆心的膨胀，不能只用一个全图径向阈值。
- **不可用状态**：低纹理、严重模糊/曝光变化、有效点不足、历史丢失、求解超时、帧龄超限进入UNKNOWN；自动行驶模式不得将UNKNOWN当作无障碍。

gyro经过IMU到相机外参变换，并在曝光/帧间时间区间积分，用标定的相机旋转模型扣除旋转流。只读Z轴再减一个像素常数不够。FOE也不一定恰好在图像中心；转弯和动态物体需单独处理。

在纯前向、近似恒速和有效FOE等假设下，令 `r_i` 为点相对FOE的位置，`Delta p_i` 为去旋转帧间位移，`Delta t` 为真实配对时间间隔：

`lambda_i = (r_i · Delta p_i) / (||r_i||² Delta t)`，`tau_i = 1/lambda_i`，仅对正扩张且远离FOE退化区域的可靠点成立。

实现时用交叉乘法比较 `tau < T_critical`，无需逐点除法；Q7流量必须包含128倍比例。跨帧丢弃/跳帧必须更新 `Delta t`，不能恒定按1/30秒计算。TTC不等于毫米距离，也不是任意运动下都精确成立。[稀疏光流、去旋转与碰撞候选原论文](https://mediatum.ub.tum.de/doc/1283833/document.pdf)、[光流扩张率及适用假设](https://pmc.ncbi.nlm.nih.gov/articles/PMC6604071/)。

建议直接导出专用安全快照 `{epoch, frame_pair, capture_time, valid, hazard, quality, age}`，在感知control50与底盘clk50m之间建立原子CDC和接收端看门狗。诊断/网络拥塞不得反压该链路；损坏帧、旧代次、源复位、PCLK停钟、感知PLL停钟均需在接收端有确定行为。

窄道模式：碰撞证据触发锁存停车；清除必须结合有效新观测、车轮静止和显式恢复，禁止因为下一帧风险下降而重新露出旧PWM。自动模式UNKNOWN也撤销行驶许可。原手动模式、ARM、STOP、租约与故障优先级保持由底盘权限逻辑管理。

### 延迟与5cm净空必须分开验收

`T_total = T_采样相位 + T_曝光/读出 + T_光流求解 + T_CDC/仲裁 + T_驱动响应`。

30fps帧周期为33.33ms，仅最坏出现相位的采样等待就可能接近一帧；新出现物体重建可靠光流可能需要额外帧。当前整帧存储/求解链路没有“障碍出现至动作<5ms”的证据。

保留 `<5ms` 作为**有效光流危险事件到驱动进入已确认制动状态**的指标，RTL可另设更紧的周期上限。必须分别报告曝光/采样等待、求解、CDC、仲裁、驱动和完全静止时间。1kHz控制更新不意味着相机提供1kHz新信息。

对于静止障碍、近似恒定减速度，保守停止净空需求为：

`D_required = D_reserve + |v| T_total + v²/(2 a_min) + D_uncertainty`。

`D_reserve=50mm` 从车头/实际足迹算起；`a_min` 是最差已测制动减速度。动态障碍还要计入其接近运动和遮挡，不能直接套静止障碍公式。Nav2的碰撞监测也使用速度、反应时间和停止距离约束；本项目将对应仲裁放在FPGA内。[官方停止包络说明](https://docs.nav2.org/rolling/tutorials/general_tutorials/using_collision_monitor/using_collision_monitor/)。

本轮数学示例：v=0.2m/s、T_total=80ms、a_min=0.5m/s²、预留50mm、额外误差10mm，需要至少116mm；v=0.4m/s时需要252mm。均为示意，不是本车测量值。固定150mm门限不适用于所有速度。

**只凭单目光流无法无条件证明最终净空≥5cm。** 它能提供碰撞风险/TTC，不能独立确定任意动态障碍的绝对距离。继续按用户要求以光流主响应，但将5cm作为在规定速度、光照/材质、障碍进入方式、覆盖范围下的外部实测指标；已有雷达继续提供能观测到的距离约束。

## 制动和控制频率

本车是AT8236 D157B有刷驱动。现有RTL中00为滑行路径；不能把“PWM清零”写成“完全制动”。新制动适配需要明确STOP/故障的滑行与短路制动策略、供电丢失行为、最大持续时间和恢复次序。11制动不是主动反转；不直接施加未经电流限制和台架验证的反向转矩。短路制动也不等于零速机械锁轮。

先以1kHz硬件控制调度为目标，但是否提升速度PI要结合编码器分辨率和实测速度估计。可采用边沿周期/滚动计数测速；低CPR下每1ms直接计数会量化严重。现有“counts/10ms”接口、Ki、斜坡、换向等待、堵转计数、遥测比例和测试必须一起重算，不能只把 `CONTROL_HZ` 改成1000。10kHz PWM载波保留为独立概念；10kHz速度闭环暂没有物理必要性证据。

雷达点周期约46.3µs，在50MHz下平均约2315拍/点，16拍迭代CORDIC算术约0.32µs，仍需另计握手/乘法/FIFO预算；解析器会成批连续输出12点，平均吞吐足够不代表可直接无缓存连接。既有规划CORDIC不能因共享仲裁卡住接收。全流水方案只有在测得资源/延迟收益后再选，不能说三角函数必然“很耗RK3588 CPU”。

## IMU修正

MPU6050没有内置磁力计；水平绕重力方向旋转不改变重力向量，`theta_acc_mag`不能从现有加速度计得到。原互补公式用于无漂移yaw的依据不成立。[ST官方说明](https://www.st.com/resource/en/design_tip/dt0140-tilt-computation-using-accelerometer-data-for-inclinometer-applications-stmicroelectronics.pdf)。

建议1kHz用去偏gyro短期传播，用编码器增量yaw辅助，双墙方向在可观测且质量合格时校正相对航向；转弯中参考方向跟随局部路径，不能锁死入巷时的全局yaw。失去墙方向时增加不确定度并降速，不能继续声称无漂移。

当前MPU6050配置为DLPF_CFG=1，手册给出的gyro滤波延迟约1.9ms，1kHz仅是输出率。曝光与IMU滤波/总线读取的时间差需要进入光流去旋转时间对齐。[MPU6050寄存器手册](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map.pdf)。

## 语义确认与10cm停靠

采用 `CRUISE → TARGET_CONFIRM → STAGING → ALIGN_APPROACH → SETTLE → DONE`，另有独立BRAKE/FAULT。红色属性与对象类别分别确认，复用现有带帧号YOLO/ROI颜色/LK接口，要求目标ID和连续观测一致；通用YOLO类别本身不会自动区分“红杯/蓝杯”。蓝杯没有语义停车请求，但只要侵入足迹，光流/几何保护仍优先停车。

侧方货架目标首先需要可行的预停靠位姿。普通差速车不能横移；在只多10～15cm的走廊内未必能转成正对侧面目标。必须先用足迹规划判断姿态可达性，必要时把演示目标放在端面或停靠凹位，而非假设“发现后原地转90°”必然成立。

水平误差建议转成标定角度 `e_beta = atan((c_x-u_target)/f_x)`，而非固定5像素作为各分辨率通用阈值。相机镜像、畸变、内参、IMU/相机/雷达外参一并校正。

将雷达点投影到相机，按检测框/跟踪ROI、角度、连续性和深度选择**属于该目标**的点簇；检查2D扫描平面确实扫到杯身。不能把整个±5°的最近点直接认作杯子，附近货架、墙角或手都可能更近。

若雷达原点在车头后方 `b_front`，正前方平面目标的雷达参考距离应是 `b_front+100mm`，不是100mm。一般情形用车体坐标点/目标表面到前保险杠的距离求解；明确“目标前方”指杯子表面，而非检测框中心/杯体圆心。

逼近使用 `v_ref = min(K_d e_d, v_approach, v_braking_limit)` 并限制角度误差/角速度；无后方安全观测时不自动倒车纠正超调。外参未确认、目标丢失、目标簇失效或光流不可用时停车。

固定15cm全障碍停车会与10cm目标距离冲突。接近模式必须显式使用低速、目标关联和100mm期望净空，独立约束任何非目标障碍；不能全局关闭安全保护，也不能把红色类别当作碰撞豁免。

内部完成条件可以设更紧的距离带，但它不能超过测量精度被解释为真实5mm精度。完成要求角度/距离连续有效0.5秒、双轮速度低于静止阈值、位姿无明显变化；真实 `100±10mm` 用独立量具测量。声光确认还需分配现有LED/蜂鸣器接口，不能假定音频阶段已经集成。

## OSD与FPGA贡献的验收口径

当前集成工程主显示链路是UDP图传，浏览器光流底图并未逐帧锁定；HDMI调试历史工程不能当作新窄道HDMI OSD已实现。新增OSD需独立核对RGB565像素格式、视频/HDMI时钟域、时序、帧号和资源。

OSD字符/轨迹可以采用扫描线流水叠加，点云图需双缓冲，显示后台更新的完整快照；图像是30fps、雷达约10Hz，必须显示各自帧龄。“无延迟”改为“固定像素流水延迟/有界显示延迟”，另测相机到屏幕延迟。

“40% FPGA价值”用可审计工作量和实测证据支撑：雷达原始输入/协议与几何处理、光流求解/安全直通、轮速调度/驱动适配、OSD、资源和最坏时延。不能把逻辑资源占比或核数量直接换算成系统贡献百分比。

## 实施顺序与验收

1. 保留本轮审核与基线；收集车宽/长、轮距、CPR、雷达到车头距离、全部外参和拐角形状。目前继续沿用 `docs/task4/calibration.pending.json` 的未确认状态，不填入示意数值作为可运行配置。
2. 建立独立窄道算法参考模型与回放夹具：墙面离群点、局部遮挡、开口、斜墙、左右扫描不同步、拐角足迹。先检查严格15mm间隙差能否达到传感器误差预算。
3. 独立RTL实现双墙估计和中心路径；保留旧导航模式，新增明确控制所有者，禁止两个模块同时给轮指令。
4. 接专用光流安全快照、CDC、接收端看门狗和窄道锁存停车；加入横穿、新遮挡、低纹理和转弯去旋转。原手动入口继续可回归。
5. 另做D157B制动适配和1kHz调度/测速升级；分别验证00滑行、11制动的真实停止时间、净空和电流/供电行为。
6. 完成数字功能、完整综合/PnR/STA及现有未决MPW检查，再做静态并发验收；随后低速直道、拐角、光流障碍、断相机/断IMU/断雷达/断主机等动态验收。
7. 最后接目标关联和终末停靠、声光、OSD，复核停靠模式下安全约束无冲突。

| 指标 | 验收方式 |
|---|---|
| 严格间隙差<15mm | 独立外部位置/间隙真值，记录速度、地面、墙材、最大误差和分位数；入巷收敛段与稳定段分别报告 |
| 拐角不碰撞 | 实际全足迹净空、转角轨迹和最小间隙；几何不可达计为场景不满足，不能靠调增益掩盖 |
| 有效事件→制动<5ms | RTL周期断言和示波器/逻辑分析仪，标记事件、CDC接收、驱动状态变化 |
| 障碍出现→完全静止 | 外部触发/高速录像与编码器，扫过完整相机相位；不能用网络回包时间代替 |
| 停后净空≥50mm | 固定最大速度和规定进入轨迹，多纹理/光照/角度/盲区测试，独立量具真值 |
| 100±10mm停靠 | 至少多次不同起始位姿，目标表面到车头外部测量；失败/丢失/超调单列，不仅报均值 |
| 1kHz调度与保护 | 采样/控制周期、最坏执行时间、测速量化和失效超时；PWM频率另报 |

本轮新增的是审核文档与可复算的数学示例；没有修改现有RTL、下载位流、连接车载服务或发送运动命令。后续具体实现与实车验收需依照上表逐项留下证据。
