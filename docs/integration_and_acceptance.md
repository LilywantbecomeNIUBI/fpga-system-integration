# 集成范围和动态验收

当前阶段：引脚规划。以下均为待做事项，尚未执行硬件操作。

## 系统职责

FPGA 负责两路有刷电机 PWM、AB 计数、轮速闭环、超时与停机，以及后续摄像头、网口、IMU、雷达、音频数据接入。Nano 承担现有视觉推理等上层任务，PC 提供统一状态、控制与记录入口。感知到运动的命令接口应先定义版本、单位、序号和超时，之后逐模块迁移。

当前底盘使用万向轮支撑，不要求俯仰平衡环；IMU 用于观测和后续融合。旧 FOC、磁编码器和电角度标定不属于该有刷电机控制链。

## 分阶段验收

1. 接线验收：确认板卡和驱动版本、编码器型号/电压/输出类型、四路电平转换、共地、急停、两轮机械安装与电源限流。
2. 电机断电验收：手转左右轮，记录 AB 波形、电平、方向、异常跳变和每输出轴转的实际计数；核实减速比和倍频定义。
3. 单轮悬空验收：限定占空比/时间，分别验证两路控制与对应编码器，确认物理链为“左/右电机—A/B驱动—IN1/2—对应AB—FPGA输入”。
4. 双轮悬空验收：验证独立速度指令、轮速环、正反转、减速停止、指令超时和停机锁存；记录电源、速度、PWM和故障状态。
5. 落地底盘动态验收：低速直行、倒车、转弯与停车，测定轮径/轮距，使用外部距离/角度依据评估运动误差，确认万向轮稳定支撑。
6. 系统动态验收：同步启用感知/网络流量，记录帧率、吞吐、轮速环周期、命令延迟、丢包、指令失联停车与各模块健康状态。逐项填写实测阈值、结果和原始日志路径，再给出通过结论。

各步骤应填写具体限值后执行；不凭空预设已通过。离线仿真、引脚检查和 STA 均不能替代上述车辆动态验收。未经确认不自动下载或运行电机。
