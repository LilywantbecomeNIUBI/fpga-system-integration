# STM32对照、IMU修正与直连候选（2026-11-02）

本记录更新此前的排查状态。用户要求先核对STM32代码，随后选择绕过转接板直接接FPGA。没有因电阻读数断定模块损坏；用户报告同样读数的传感器在STM32上能够通信。用户已确认模块插回过转接板，SCL上拉已拆。

## 已修改的代码

- `fpga/imu/mpu6050_reader.v` 同时接受MPU6050的WHO=0x68与MPU6500的WHO=0x70。MPU6500按参考STM32工程配置滤波与中断寄存器，并增加ACCEL_CONFIG2（0x1D=0x02）；MPU6050保留自身配置。地址仍是AD0低对应的0x68，WHO身份值不作为总线地址。
- IMU状态及独立UART输出为MPU6500使用config_id=6；共享解析器、只读验收工具支持此身份，温度采用MPU6500对应换算，六轴量程保持一致。
- 新增独立只读I²C身份探测控制器和诊断顶层，可报告三个应答阶段、引脚拉低回读异常与超时。生产I²C控制器没有为了掩盖NACK改成推挽输出。
- 新增MPU6500行为仿真、主机协议测试，以及两套I²C控制器在延迟引脚模型下的对照测试。

参考STM32工程实际使用I2C2 PB10/PB11、开漏、400kHz，读取序列为D0/寄存器/重复START/D1；代码同时接受WHO=0x68/0x70。STM32历史有效采样记录支持MPU6500身份。FPGA旧版只接受0x68确实需要修正，但它不能解释从第一个地址字节就没有应答的问题。

## 实测状态

COM25曾出现Windows设备错误，USB重连后已恢复。修正身份兼容后的原F19/F20静态诊断固件已重新下载SRAM；最新10秒采集得到79,568字节、混合帧CRC错误0、49圈完整雷达扫描。IMU仍只有10条故障状态，WHO=0，未获得有效六轴样本。电机未解锁，输出为0。

独立100kHz只读探测在0x68、0x69均于首个地址字节NACK。临时交换软件SCL/SDA映射后仍无应答；拉低回读异常随物理F19从SCL转到SDA。该结果未确定根因，也没有证明转接板或模块损坏。探测后恢复了修正身份兼容的原引脚静态固件；没有写Flash。

对照仿真已验证700ns SCL上升延迟、3us从机数据/ACK延迟、三处NACK、重复START及超时恢复，未复现生产控制器时序故障。仿真通过不能替代实际引脚波形。

## 新的直连接线与构建

先断电，将模块从转接板拔下，断开转接板与FPGA的P7排线；以下针号均指FPGA板P7插座。

| 模块引脚 | FPGA连接 |
| --- | --- |
| VCC | P7-29，3.3V |
| GND | P7-30，GND |
| SCL | P7-31，F16 |
| SDA | P7-32，E17 |
| AD0 | 模块GND |
| XDA/XCL/INT | 悬空 |

这是专用M2静态诊断映射，必须配套直连位流使用。旧F19/F20位流及其他使用F16/E17编码器的固件不能直接套用此接线。

直连候选已通过行为仿真与Gowin完整布线：Setup/Hold违规0/0，最小脉宽裕量+7.363ns，十二路电机控制输出在网表中均固定为GND，没有运动命令接收入口。位流SHA256为`98ff3b3158347c68834f0b09c9cd5c216c485b56a519ea32f6fd6cbefe0d6295`。

**直连候选尚未下载，用户尚未确认接好线，IMU实板通信未通过。** 载板排线拔下后的雷达离线不作为本次直连IMU测试的失败条件。下一步是确认接线后下载匹配位流，再检查真实WHO、ready、连续样本序号和CRC。
