# STL-27L 全点以太网上传：离线交付记录

日期：2026-11-02。此版接续 360 点方案，将网口上传改为雷达解析器输出的全部采样点。**本轮没有下载、复位 FPGA、改写网络目标、启动新网关或替换正在运行的上位机。**

## 最终行为

- 雷达不再按 1°/5°扇区取最近点后上传。每个通过原生 CRC8 检查的 STL 数据包，其 12 个解析点全部上传，包含重复角度、距离为零和强度为零的采样。
- 距离和强度与原始包逐点一致。角度沿用 FPGA 解析器根据包首尾角度插值得到的 0.01°定点值；它不是对原生 47 字节包的逐字节镜像。相对浮点参考角度，四舍五入误差不超过 0.005°。
- 实际记录回归的完整圈分别有 **2177 / 2175 / 2175 点**。圈点数随雷达转速和采样情况变化；本方案没有提高雷达的物理采样率或转速。
- 上位机默认显示全量有效回波，可选 720 / 360 点上限。选项只作用于绘图，按角度区间选真实近点，原始接收数据和记录仍保留全量。
- 显示范围默认自动覆盖全部有效回波；固定 3 / 5 / 10 / 25 m 时显示超范围点数。零距离/零强度点保留在数据中，不画成障碍物。
- 雷达、IMU、电机状态、编码器诊断/轨迹、导航状态和雷达诊断全部使用 UDP 6205。控制命令保留原 UART 链路。

## 传输、资源和接收开销

每个原生 12 点包拆成两个 6 点状态帧，复用原有 48 字节内帧、CRC16 和 64 字节 `TLM1` UDP 载荷。这样沿用现有仲裁、CDC 邮箱和 MAC，不增加整圈缓冲。

按 21600 点/秒估算，仅雷达约 1800 原生包/秒、3600 UDP 包/秒：

| 口径 | 流量 |
|---|---:|
| 点元组（每点 5 字节） | 108000 B/s |
| 48 字节内帧 | 172800 B/s |
| UDP 应用载荷 | 230400 B/s |
| 含以太网/IP/UDP、前导码、FCS 和帧间隔，按每包 130 字节 | **3.744 Mbit/s** |
| 占 1 Gbit/s 线速 | **约 0.3744%** |

以上不含视频及其他状态流量。带宽余量不能等同于整机实际负载测试；本轮只完成数字验证。

雷达源采用 8 包 FIFO，256×32 位同步 RAM，只有窄端口读写，无整圈数组。静态传感器诊断版布局布线报告如下；这是包含 PHY/MAC、IMU 和静态底盘状态的整个顶层，不代表完整视觉融合工程的利用率。

| 资源 | 前一 360 点网口诊断版 | 本次全点网口诊断版 |
|---|---:|---:|
| Logic | 15300 / 138240，12% | **15377 / 138240，12%** |
| 寄存器 | 17678，13% | **18530 / 139095，14%** |
| BSRAM | 4% | **2 / 340，不到 1%** |
| DSP | 2% | **4 / 298，2%** |

接收端 CRC16 改用标准库 `binascii.crc_hqx`，初始值和多项式保持不变；通过独立逐位参考、已有控制/遥测测试和 RTL 报文检查。日志保留逐包原始帧与索引，改为每 64 条或约 100 ms 批量刷新，并在关闭时写完尾部。

开发机离线测量：不记录时约 8.1 万包/秒；以 3600 包/秒输入并记录时，2000 个报文和 4000 条索引均完整，队列丢失为零。该测量来自 Windows 开发机，**不是 Nano 实测 CPU 占用**。证据为 `receiver_benchmark.json`。

## 数据格式和完整性

保留此前 `TLM1` 16 字节外头：版本 1、保留零、网络序发送序号及 FPGA 毫秒时间，再接 48 字节内帧。

新雷达点内帧的多字节整数均为小端：

| 字节 | 内容 |
|---|---|
| 0..3 | `C3 3C 07 01` |
| 4..7 | 原生有效包序号 uint32 |
| 8..9 | 源端排队年龄 ms，必须小于 400 |
| 10..13 | FPGA 捕获该包的毫秒时间 uint32 |
| 14 | 半包编号 0 / 1 |
| 15 | bit0：解析器错误计数发生变化，其他位为零 |
| 16..45 | 6 组角度 uint16（0.01°）、距离 uint16（mm）、强度 uint8 |
| 46..47 | 与既有状态帧相同的 CRC16 |

雷达诊断为 `C3 3C 06 03`：前七个 uint32 计数仍为 device_ms、bytes、framing_errors、packets、crc_errors、format_errors、timeouts；最后两个 uint32 改为 forwarded_packets、dropped_packets；结尾 uint16 为 0..8 的完整包排队数。旧 72/360 点解码仍兼容。

源端超过 FIFO 容量或 400 ms 年龄会显式计入丢弃。主机检查原生包序号、两个半包的元数据一致性、包间角度连续性、捕获时间和错误标志；有缺片/缺包/解析器错误的圈不发布为完整圈，收到下一圈连续数据后恢复。重复或过期数据不能刷新旧扫描的新鲜度。通用 UDP 序号缺口单独计数，雷达完整性依据原生包/半包判定，避免仅丢失一帧其他状态时误删雷达圈。

7. 完整相机/导航 `system_task4_top` 全点候选已冻结并通过层次展开。**该完整融合候选没有完成本轮 PnR，也没有实板验收。**
