## 已实施的修改

- 图传：行缓存增加输出寄存器，预取下一像素。只在当前高字节被消费后切换输出，
  任意暂停不能改写正在发送的像素。综合网表的行缓存`READ_MODE=1`。
- 独立光流避障：乘积寄存器去掉不必要的数据复位，由复位/失效后的valid标签隔离；
  将点积/范数加法、阈值判别、区域计数使能拆开，综合网表确认四个相关DSP
  `OREG_CLK="CLK0"`。区域、样本有效性、帧完成及帧号同步延迟，帧完成需等待
  最后样本计数完成。状态包使用锁存的`status_id`，新帧开始会清除旧流水标签。
  消费端通过通用`OUTPUT_DRAIN_CYCLES=4`参数延长帧缓存所有权；裸光流默认0。
  求解完成后流水线排空前到来的完整帧，仍按原有过载规则整帧丢弃，不能释放旧bank
  并提前启动下一对图像。该参数不引用底盘或控制器。
- 检测反馈：帧龄差值独立寄存一拍，并携带对应的上一结果帧号；刷新结果后，旧流水
  中的过期判断不能清除新结果。帧龄失效增加一个125MHz周期，原有毫秒超时截止
  周期及停止摄像头后的拒绝逻辑保持不变。
- 网络秒计数器：按`$clog2(CLK_HZ)`缩位，生产125MHz下为27位；末值预判寄存
  一拍，仍在原来的第125000000个周期触发。LK观测超时计数器按参数缩到26位。
- SDC：手写生成时钟的对象改为PLL输出`CLKOUT0/CLKOUT1`引脚。保持50/84/125MHz、
  原有IO时序假设及CDC边界，没有新增多周期或宽泛的false path。
- 构建判定：Setup/Hold、最小脉宽、PR1014时钟路由告警分别记录；仅Setup/Hold为0
  不会把整体构建标记成通过。每次构建保存独立的SDC/CST及报告。

## 对原诊断的核实

流水线切分与按范围缩短计数器有效。但以下推断不能仅从原报告直接成立：

1. `camera/clk125`原本已经使用PRIMARY全局时钟。时钟高扇出是正常现象，
   不能据此判定缺少全局缓冲。SDC允许以net或pin为对象；改绑pin后需要再看实际报告。
2. 秒计数器原来的RTL本来就是条件清零、否则`+1'b1`，并没有复杂函数表达式。
   综合器选择LUT实现的现象成立，但不能把原因归结为源码使用了复杂加法写法，
   也不能承诺改写模板就一定使用ALU或得到指定的纳秒裕量。
3. 本版高云工具手册说明了PLL自动派生和`create_generated_clock`；没有套用其他
   厂商的`derive_pll_clocks`命令。
4. 摄像头PCLK原本已经有`CLOCK_LOC "camera_pclk_d" BUFG = CLK;`，
   布局报告也确认其主干为PRIMARY。B1对应IOL2[A]/ADCINCK0，入口不是专用
   GCLK引脚；已有全局主干约束不能把普通IO脚变成专用时钟输入。

## 时钟诊断边界

修复后的第一次完整布线`20261030T120150Z`：Setup/Hold=0/0，最差Setup为
`+0.010ns`，但RAM脉宽仍为actual `0.212ns`、required `0.900ns`、slack
`-0.688ns`，PR1014也仍存在。因此“改绑PLL引脚即可消除脉宽违例”未获验证。

同器件、同PLL配置的独立小工程比较了手写pin约束与工具自动派生：两者的125MHz
频率、相位和BSRAM高脉宽结果一致（小负载下均为1.565ns、裕量+0.665ns）。
这项结果用于比较约束语义，不能替代完整合并工程的负载/布线结果。
额外DCE的诊断试验没有消除B1入口的PR1014，且其125MHz RAM脉宽更差，
没有移入主工程；PCLK经过DCE后还需要显式派生时钟约束，不能接受工具默认100MHz。

当前完整工程MPW详细路径的计算为：晚到上升沿`3.835+3.341=7.176ns`，
早到下降沿`4+1.869+1.519=7.388ns`，差值为0.212ns。
这包括STA的早/晚时钟模型，不能声称是示波器测得的真实脉宽。
此项仍需核查时钟网络的早/晚模型及工具处理；没有用改变占空比、false path或
将输出定义为无关基础时钟来掩盖它。

PR1014的彻底排除涉及板级可用GCLK入口与实际接线，不能只改CST中的球号并认为
现场连线已经改变。B1现有接线保持原状。

手册依据为本机高云V1.9.12.04配套SUG940-2.0.5E（生成时钟/PLL自动派生）、
SUG1541-1.0E §2.8（CLOCK_LOC）、SUG937-1.1E PR1014及UG306-1.0.9E。
