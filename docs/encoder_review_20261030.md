# 有刷AB编码器资料、RTL与实测日志复核（2026-10-30）

## 结论

现有证据支持“累计非法跳变不等于位置持续错误”。清零复测中的1188次错误集中在位置不变的一小段，之后有较长的有效位置变化且不再报错。不能再仅凭累计值非零，就判断编码器持续失效或禁止一切后续验证；也不能据位置数字有变化就认定精度、方向、左右映射及100Hz速度反馈均已通过。

物理根因尚未确定。实际A/B原始状态轨迹和具体手转动作没有同步标记，无法把异常定为器件损坏、串扰、接线错误、供电变化或RTL/实现故障。本次只做离线研究，未修改生产RTL/保护门限、未下载、未发运动命令。

## 对照当前RTL

`fpga/motor/encoder_ab.sv`使用50MHz时钟、两级同步，候选AB二位向量稳定后更新stable。默认FILTER_CYCLES=8，从候选建立到稳定提交约9个时钟（约0.18us），另外还有同步、译码寄存器延迟；不是8ms级去抖。

正常状态变化每次只翻转一位，四倍频增减计数；previous XOR stable为11时累计invalid_count，但step=0，位置和窗口计数都不增加。两位跳变既可能是漏掉中间状态，也可能是两路相关扰动；现有计数不能区分二者。

共同AB稳定滤波不会保留任何比稳定门限更短的中间状态。因此在不知道实际最短有效相间隔前，不应盲目大幅加长滤波；否则可能将原本可解码的相邻变化合并成对角跳变。手转下滤波门限是否是主因仍需实际波形，不凭50MHz名义频率作结论。

通用四倍频解码中把对角状态变化视为无方向信息并忽略，并非本工程特有规则。参考Microchip QEI参考手册Table 15-1，第15-3页：<https://ww1.microchip.com/downloads/en/devicedoc/s15.pdf>。这不意味着Microchip硬件的输入滤波与本工程完全等效。

该模式符合“对角扰动被忽略、随后正常计数”的一种解释，但现有数据不能证明具体电气原因，也不能证明之前没有丢数。归纳为持续位置失真过于武断；将累计错误当作完全无害也证据不足。

## 保护与下一步

当前FPGA保护不是“累计非零就停机”。`motor_core.sv`每10ms更新上次计数，只在已ARM且某轮本周期新增大于8时锁存bit2。STOP状态也更新统计基线，所以历史累计1188不会在下一次ARM时自动等价为本周期1188次。诊断累计不应直接作为全程有效性判据；现有20Hz日志也不足以反推出每个10ms窗口是否会越界。阈值8是本工程初版值，不是厂家规定。

优先验证“计数是否可信”：供电稳定、STOP下明确标记单轮动作起止，检查只转一轮时另一轮不跟随；标记轮子起点，重复同向整圈计数并检查重复性，再验证往返一致性（考虑减速箱回差、编码器分辨率和手转定位误差）。同时按运动段/非运动段分别统计新增非法跳变，而不是只读总数。不能用尚未确认的Xp28减速比和霍尔/GMR线数算伪精确RPM。

如果仍有“位置不变但invalid快速增加”的段，下一项固件诊断应记录原始AB边沿、滤波后AB、对角跳变方向（00↔11或01↔10）、合法正/负增量和100Hz窗口统计，并保留独立停机。由这些证据决定是否需要独立双通道滤波、滤波参数调整或保护策略调整；本次没有屏蔽保护。
