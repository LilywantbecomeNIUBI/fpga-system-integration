# LK状态反馈与地址时序改动（2026-10-31）

本轮检验状态寄存器复制与异常跳转的相关性；尚不能把此前的异常认定为亚稳态、
PCLK抖动或某一条STA路径导致。二进制状态机在满足时序时允许多位翻转，
独热编码也通常有两位翻转。此前18个指5位状态展开后的触发器总数，并非18套完整状态机。

基线报告全局最差Setup为eth125域0.000ns；cam_pclk最差为+0.007ns，
起点环境LK的sy，终点read_address。目标跟踪器point_y到state另有+0.029ns临界路径。

## 修改

- `flow_lk_patch`采用显式5位Gray码，WAIT_RAM=00010，LATCH=00110，
  该边只翻转一位。分支与回边并非全部单比特转换，不以编码替代时序约束。
- 状态寄存器施加`syn_preserve=1`；单独使用该属性仍产生16个状态触发器，故不能作为禁止复制的证明。
  `replicate_resources=0`单独也不能取消综合阶段由max_fanout引出的复制。
- 根据本机SUG550-2.4E第5.11/5.13节，对主状态数据寄存器覆盖`syn_maxfan=100000`，
  避免全局32扇出阈值拆分主状态，同时保留`syn_preserve`并关闭PnR资源复制。
  这与先前给CE信号施加无效syn_maxfan不同：本处对象是状态数据寄存器，最终以网表检查为准。
- 两个LK实例与上层vision_tracker的综合检查均为每位一个、每个向量5个主状态触发器。
  `tools/audit_lk_state.py`遇到多副本或缺位即失败；它检查综合网表，不冒充布局布线后仿真。
- REQUEST寄存行列与偏移选择，ADDRESS分别计算行乘积和列偏移，ISSUE才执行最终加法并发出读请求，
  随后仍经过WAIT_RAM、LATCH，保持同步RAM读取语义。
- 9×9位fabric乘法拆为高/低部分积再求和，增加PRODUCT_SUM状态，保持有符号固定点数值不变。
- 主状态之外增加32位寄存译码，以next_state前视对齐数据操作，不增加额外状态周期。
  两个LK主状态位的最大直接扇出分别为15、19，原对照版环境LK最大为223。
  上层vision_tracker保留单份二进制状态；本次寄存译码改动覆盖两个LK求解器实例。
- 保留非法状态及IDLE/busy矛盾的无效完成、自恢复和首次故障锁存。
  黑匣子保留原始状态位；本候选中的状态数字按Gray编码解释，不能套用旧二进制编码表。

MPW和B1接线边界沿用先前记录，不改变PLL或主时钟约束来消除报告。

## 最终结论：结构改动完成，实板验收失败

最终候选bitstream：`f4bc87aa3a861bb4f577556455cf95395e1a2042c61acf7d62967a3a3616840b`。
综合网表：`0d35d3d9370f8f6df383e46c02489cd3933f1d1ca3faa4342d5385d5bbf7ebb7`。
已完成SRAM下载，未写Flash，未发送ARM或运动指令。
Place 2、TimingDriven 1、replicate_resources 0；Setup/Hold违例0/0，
全局最差Setup +0.018ns，报告中cam_pclk最差+0.092ns。
这些是现有约束下的名义STA结果，不代表已有充分抖动裕量或整体签核通过。

最终版本仍再次锁存异常：**ADDRESS(27,11011) → 非法码18(10010)**；
正常应为ISSUE(26,11010)。首个带锁存的原始诊断上报帧为3215，
该上报帧不是异常发生那个边沿的精确帧号。
正常边27→26仅翻转一位；18还改变了本应保持为1的bit3。
因此，不能仅以最初011→100的多位翻转解释，也不能把取消复制当作已经充分修复根因。

按实际LUT INIT和CE，在主状态为27、复位无效、组合逻辑稳定的假设下，
两个真实综合网表实例均得到下一状态26，五位CE均为1。
这只检查该条件下的逻辑方程，不能证明时钟、保持时序、复位或物理实现可靠。

## 对照与传输排查

未加寄存译码的Gray对照候选为`bd106766c179adc594ba8c62764bded6ee5bb429e72abd9580a70cb21ea3b8a2`。
它曾在两个五分钟窗口里没有状态故障，之后仍触发：首个锁存上报帧35197，
记录为ISSUE(26)→非法码18，正常应为WAIT_RAM(2)。
因此“五分钟无故障”本身不能替代更长时间及物理条件验证。

前两个窗口各有一次超过200ms的避障状态过期。Nano原6202 socket存在大量累计溢出，
加入独立接收进程后，原始OFST连续到达，仍发现一次HTTP缓存过期。
最终新增可选事件进程和独立UDP转发：Nano 6202接收，6203转发至PC 6204；
PC按配置校验来源，不再依赖YOLO HTTP轮询取得核心光流状态。
过旧OFST不转发，接收进程保留内核时间戳年龄，200ms失效阈值没有放宽。
最终窗口控制年龄始终低于200ms，仍因FPGA故障锁存而未通过健康验收。
